# components 영역 기준

## 책임

`components/`는 여러 화면에서 쓰는 공용 UI와 도메인별 작은 화면 조각을 가진다. 이 영역은 표시와 상호작용을 맡고, 예치금·재고·승인 같은 최종 업무 변경은 서버 액션으로 넘긴다.

`components/ui/`는 shadcn/ui 기반 공용 컴포넌트다. 도메인 전용 문구나 업무 상태 판단을 이곳에 넣지 않는다.

도메인 폴더는 입고, CS 문의, 가이드, 관리자 상세 패널처럼 특정 화면군에 가까운 컴포넌트를 가진다. 같은 도메인 상태 배지나 목록 조각은 여기서 재사용한다.

## 경계

컴포넌트에서 Supabase 클라이언트로 직접 업무 데이터를 변경하지 않는다. 변경은 서버 액션 props나 form action을 통해 수행한다.

공용 컴포넌트에 관리자 전용 문구나 고객 전용 권한을 넣지 않는다. 권한에 따라 달라지는 버튼은 상위 화면에서 표시 여부를 결정한다.

상태 색상만으로 의미를 전달하지 않는다. 배지 텍스트, 버튼 라벨, 오류 문구가 함께 있어야 한다.

## UI 방식

운영 화면은 고밀도 테이블, 명확한 액션 버튼, 작은 상태 배지를 우선한다. 카드 중첩, 큰 장식 영역, 반복 애니메이션은 사용하지 않는다.

금액, 수량, 날짜, 송장번호는 스캔하기 쉬워야 한다. 금액은 원화 표기와 우측 정렬을 유지하고, 송장번호와 숫자는 줄바꿈이나 폭 문제를 확인한다.

폼 오류는 필드 근처에 표시하고, 전체 실패는 화면 상단이나 버튼 근처에서 바로 읽히게 한다. 토스트만으로 중요한 실패를 전달하지 않는다.

모바일에서는 관리자 테이블 액션의 터치 영역을 충분히 둔다. 작은 아이콘 버튼만 있을 때는 접근 가능한 이름이 있어야 한다.

## 테스트 기준

상태 배지, 첨부 목록, 댓글 폼, 업로드 폼처럼 조건 분기가 많은 컴포넌트는 상태별 렌더링 테스트를 우선한다.

폼 컴포넌트는 로딩 중 중복 제출 방지, 성공 후 이동, 실패 메시지 노출을 확인한다.
