# supabase 영역 기준

## 책임

`supabase/`는 데이터베이스 구조, RLS 정책, RPC, Storage 정책, 로컬 Supabase 설정을 가진다. 엑시트몰의 예치금, 재고, 배송대행, 입고, 문의의 최종 데이터 계약은 마이그레이션에 남는다.

## 경계

이미 적용된 마이그레이션 파일을 수정하지 않는다. 새 변경은 새 타임스탬프 파일로 추가한다.

RLS를 끄거나 넓히는 변경은 고객 간 데이터 분리를 깨뜨릴 수 있다. 정책을 완화할 때는 어떤 사용자, 어떤 행, 어떤 작업이 열리는지 SQL 조건으로 설명 가능해야 한다.

RPC가 맡는 원자적 변경을 앱 코드로 옮기지 않는다. 승인, 차감, 적립, 기록 생성은 부분 성공이 남으면 안 된다.

## 구현 방식

상태 값은 테이블 CHECK, TypeScript 타입, 배지 라벨, RPC 분기가 함께 맞아야 한다. 상태 하나를 추가하면 네 곳을 모두 확인한다.

관리자 판정과 활성 사용자 판정 함수는 RLS에서 반복 사용된다. 성능 최적화를 위해 initplan 형태를 적용한 정책은 되돌리지 않는다.

Storage 정책은 버킷별로 공개 여부와 소유권 기준을 분명히 한다. 상품 이미지는 공개 읽기 가능하지만, 주문·입고·문의 파일은 소유자와 관리자만 접근한다.

RPC 오류는 앱에서 업무 메시지로 매핑할 수 있는 안정적인 접두어나 명확한 메시지를 유지한다. SQL 내부 예외를 그대로 사용자에게 노출하는 방식으로 새 함수를 만들지 않는다.

## 테스트 기준

마이그레이션을 추가하면 로컬 `db reset`을 통과해야 한다. 스키마 변경 후 `lib/db-types.ts`를 다시 생성한다.

RLS나 RPC를 바꾸면 관리자, 소유자, 다른 고객, 비활성 사용자, 2그룹 사용자의 허용·거부 케이스를 테스트한다.
