# 관리자 사입재고 수기 관리 설계

## 배경

사입재고 배송대행은 입고리스트에서 `completed` 처리된 재고를 `purchased_inventory_lots`에 로트로 저장하고, 사용자가 사입재고 배송대행을 요청하면 업로드 시점에 FIFO로 재고를 배정한다. 배정된 수량은 `purchased_shipping_allocations`에 pending 예약처럼 저장되고, 관리자 승인 시 해당 로트의 `remaining_quantity`에서 실제 차감된다.

운영 중에는 입고리스트 엑셀에 없는 재고를 관리자가 수기로 추가하거나, 기존 로트의 상품명, 옵션명, 남은 수량을 바로 교정해야 할 수 있다. 이 기능은 사입재고 배송대행에만 적용한다.

## 목표

- 관리자가 사용자별 사입재고 배송대행용 재고를 직접 추가할 수 있다.
- 관리자가 기존 사입재고 로트의 상품명, 옵션명, 남은 수량, 메모를 수정할 수 있다.
- 수기 추가 재고도 기존 사입재고 배송대행의 FIFO 배정, pending 예약, 승인 차감 흐름에 포함된다.
- pending 배송대행 요청이 이미 예약한 재고는 안전하게 보호한다.
- 수기 변경 이력을 남겨 운영자가 사후에 조정 사유를 확인할 수 있다.

## 제외 범위

- 엑시트몰 배송대행 재고 관리 변경은 포함하지 않는다.
- 사용자가 직접 사입재고를 추가하거나 수정하는 기능은 포함하지 않는다.
- 로트 삭제 기능은 포함하지 않는다. 필요하면 남은 수량을 0으로 수정한다.
- pending 배송대행 요청의 자동 재배정은 포함하지 않는다.

## 접근 방식

관리자 사용자 상세 화면에 `사입재고 관리` 섹션을 추가한다. 기존 관리자 화면에는 엑시트몰 상품 재고 조정과 수기 보유 재고 관리가 이미 있으므로, 같은 사용자 상세 화면에서 사입재고까지 함께 관리하는 것이 가장 작고 일관된 변경이다.

사입재고 데이터는 기존 `purchased_inventory_lots`를 계속 사용한다. 새 재고 풀을 만들지 않고 같은 테이블에 수기 로트도 저장해야 배송대행 업로드 시 기존 FIFO 배정 로직을 그대로 사용할 수 있다.

## 데이터 모델

`purchased_inventory_lots`를 수기 로트를 표현할 수 있게 확장한다.

- `inbound_request_id`: nullable로 변경한다.
- `source_type`: `inbound_request` 또는 `admin_manual`.
- `updated_at`: 마지막 수정 시각.
- `updated_by`: 마지막 수정 관리자.

기존 입고리스트 완료 로트는 `source_type = 'inbound_request'`로 취급한다. 신규 수기 로트는 `inbound_request_id = null`, `source_type = 'admin_manual'`로 저장한다.

변경 이력을 위해 `purchased_inventory_lot_adjustments` 테이블을 추가한다.

- `lot_id`, `user_id`, `admin_id`
- 변경 전후 `product_name`, `option_name`, `remaining_quantity`
- 변경 전후 관리자 메모
- `created_at`

관리자 메모는 owner-readable `purchased_inventory_lots`에 저장하지 않고 이력 테이블에만 저장한다. 이력 테이블은 관리자만 조회하고 기록할 수 있게 RLS를 설정한다.

## RPC

클라이언트가 직접 테이블을 수정하지 않고 관리자 전용 RPC를 통해 처리한다.

`admin_add_purchased_inventory_lot`

- 입력: 대상 사용자, 상품명, 옵션명, 수량, 메모.
- 관리자 권한을 확인한다.
- 상품명은 1~100자, 수량은 1 이상 정수로 검증한다.
- `purchased_inventory_lots`에 `admin_manual` 로트를 추가한다.
- 추가 이력을 `purchased_inventory_lot_adjustments`에 기록한다.

`admin_update_purchased_inventory_lot`

- 입력: 대상 사용자, 로트 ID, 상품명, 옵션명, 남은 수량, 메모.
- 관리자 권한을 확인한다.
- 대상 로트를 `for update`로 잠근다.
- 해당 로트의 pending 사입재고 배송대행 예약 수량을 계산한다.
- 새 `remaining_quantity`가 예약 수량보다 작으면 거부한다.
- 예약 수량이 1 이상이고 상품명 또는 옵션명이 변경되면 거부한다.
- 허용되는 변경이면 로트를 업데이트하고 변경 이력을 기록한다.

## 예약 안전장치

선택 정책은 안전 제한형이다.

- pending 사입재고 배송대행에 예약된 수량보다 남은 수량을 낮출 수 없다.
- pending 예약이 있는 로트는 상품명과 옵션명을 변경할 수 없다.
- 관리자가 수정하는 동안 새 배송대행 요청이 같은 로트를 동시에 예약하지 못하도록 로트 행을 잠근 뒤 검증한다.
- 승인 RPC의 기존 `remaining_quantity >= 차감수량` 방어는 그대로 유지한다.

## UI

관리자 사용자 상세 화면에 `사입재고 관리` 섹션을 추가한다.

목록에는 다음 정보를 표시한다.

- 상품명
- 옵션명
- 총 입고수량
- 남은 수량
- pending 예약 수량
- 출처: 입고리스트 또는 관리자 수기
- 생성일 또는 최근 수정일
- 관리자 메모

추가 폼은 상품명, 옵션명, 수량, 메모를 입력받는다.

수정 폼은 상품명, 옵션명, 남은 수량, 메모를 입력받는다. 예약 중인 로트는 상품명/옵션 입력을 비활성화하거나 저장 시 명확히 거부한다. 남은 수량 입력 옆에는 예약 수량을 함께 보여준다.

## 오류 처리

관리자에게 운영 가능한 문구로 반환한다.

- 예약 수량 미만 감소: `현재 예약 3개가 있어 남은 수량을 2개로 줄일 수 없습니다.`
- 예약 중 상품명/옵션 변경: `검토대기 배송대행에 사용 중인 재고는 상품명/옵션을 변경할 수 없습니다.`
- 권한 없음: `관리자만 처리할 수 있습니다.`
- 대상 없음: `사입재고를 찾을 수 없습니다.`
- 잘못된 수량: `수량은 1 이상이어야 합니다.`

## 테스트

- 관리자 전용 RPC가 비관리자 호출을 거부한다.
- 관리자가 수기 사입재고 로트를 추가할 수 있다.
- 수기 로트가 사입재고 배송대행 업로드 배정 대상에 포함된다.
- pending 예약 수량보다 낮은 남은 수량 수정이 거부된다.
- pending 예약이 있는 로트의 상품명/옵션 변경이 거부된다.
- 예약이 없는 로트는 상품명, 옵션명, 남은 수량 수정이 가능하다.
- 수정 이력이 `purchased_inventory_lot_adjustments`에 기록된다.

## 구현 메모

기존 `fetchPurchasedLotsForUpload`는 `inbound_requests!inner(status)` 조인을 사용한다. 수기 로트는 `inbound_request_id`가 없으므로 이 조회를 바꿔야 한다. 조건은 `source_type = 'admin_manual'` 또는 연결된 입고리스트가 `completed`인 로트로 확장한다.

사용자 사입재고 목록 요약도 같은 기준을 사용해야 한다. pending 예약 계산은 기존 `purchased_shipping_allocations`와 pending `order_uploads` 기준을 재사용한다.
