# 배송대행 배송비 정책, 장바구니 재고 알림, 상품명 공백 매칭 설계

## 배경

2026-05-20 요청은 기존 엑시트몰 배송대행/사입재고 배송대행 분리 흐름 위에 세 가지 동작을 조정한다.

1. 엑시트몰 배송대행 승인 시 배송비가 예치금에서 차감되지 않게 한다.
2. 장바구니 단계에서 재고 부족을 미리 알리고 주문 진행을 막는다.
3. 배송대행 양식 업로드 시 상품명 공백 차이는 무시하고 글자만 일치하면 매칭되게 한다.

사입재고 배송대행은 이미 승인 시 입고완료 재고만 차감하고 예치금은 차감하지 않는다. 이번 변경은 그 정책을 엑시트몰 배송대행에도 맞추되, 엑시트몰 상품 구매 금액의 예치금 차감은 그대로 유지한다.

## 목표

- 상품 구매 승인 시 상품 금액은 계속 예치금에서 차감한다.
- 엑시트몰 배송대행 승인 시 보유 재고만 차감하고 배송비는 안내 금액으로만 표시한다.
- 예치금 가용액/검토대기 예약액 계산에서 배송대행 배송비를 제외한다.
- 장바구니에서 현재 재고보다 많은 수량이 담긴 상품을 명확히 표시하고 검토 요청으로 진행하지 못하게 한다.
- 엑시트몰 배송대행과 사입재고 배송대행 모두 상품명 비교 시 공백 차이를 무시한다.

## 비목표

- 배송비 미수금, 계산서, 별도 정산 내역을 새 데이터 모델로 만들지 않는다.
- 상품 구매 흐름의 예치금 차감 정책은 변경하지 않는다.
- 장바구니를 서버 저장형으로 바꾸거나 기기 간 동기화하지 않는다.
- 상품명 공백 차이 외의 오타, 약어, 유사어, 대소문자 차이까지 포괄하는 확장 검색은 이번 범위에 포함하지 않는다.

## 설계 1: 배송대행 배송비 정책

엑시트몰 배송대행 승인 RPC는 `upload_type = 'exitmall'` 업로드에 대해 재고 차감만 수행하고, `profiles.deposit_balance` 차감과 `balance_transactions` 배송비 차감 기록을 생성하지 않는다. 기존 사입재고 배송대행의 "재고만 차감" 정책과 같은 방향이다.

`shipping_fee_total`은 삭제하지 않는다. 목록, 상세, 엑셀 행 요약에서 "안내 배송비" 또는 "별도 정산 배송비"로 계속 표시한다. 운영자가 행 수 기준 배송비를 확인할 수 있어야 하기 때문이다.

예치금 화면의 가용액 계산은 pending `stock_orders.total_amount`만 예약으로 계산한다. pending 배송대행의 `shipping_fee_total`은 더 이상 예약액에 포함하지 않는다. 따라서 "검토대기 예약" 문구와 README/가이드의 설명도 상품 구매 대기 금액 중심으로 수정한다.

관리자 엑시트몰 배송대행 상세에서 "가용 예치금이 배송비보다 부족합니다" 경고는 제거한다. 승인 버튼과 토스트 문구도 "보유 재고 차감" 중심으로 바꾼다.

## 설계 2: 장바구니 재고부족 알림

사용자 레이아웃에서 `CartProvider`에 상품별 `stock` 값을 함께 넘긴다. 기존 `per_user_limit`, `alreadyBought` 정보는 유지한다.

`stock = -1`은 무제한 재고로 취급한다. 그 외에는 장바구니 수량이 현재 재고를 초과하면 해당 항목을 부족 상태로 판단한다.

장바구니 화면은 부족 상품 행에 경고 메시지를 표시한다. 예시는 다음과 같다.

> 현재 재고 3개라서 5개 주문할 수 없습니다.

부족 상품이 하나라도 있으면 "주문하기" 버튼을 비활성화하고, 수량을 낮추도록 안내한다. 사용자의 수량을 자동으로 줄이지 않는다.

상품 카드의 담기 버튼도 현재 재고 이상으로 더 담을 수 없게 맞춘다. 기존 품절/품절 임박/1인 구매 제한 표시는 유지하며, 제한 수량과 재고 수량 중 더 작은 값이 장바구니 최대 수량이 된다.

서버의 `request_stock_order` 재고 검증은 그대로 유지한다. 장바구니 검증은 사전 안내이고, 동시 주문 또는 관리자 재고 조정으로 생기는 최종 경합은 서버가 막는다.

## 설계 3: 상품명 공백 무시 매칭

배송대행 업로드의 상품명 비교는 비교용 정규화 키를 사용한다. 정규화는 유니코드 NFKC 적용 후 모든 공백 문자를 제거하는 방식이다.

예시는 모두 같은 키로 본다.

- `안국약품 토비콤`
- `안국약품  토비콤`
- `안국약품토비콤`

엑시트몰 배송대행은 기존 우선순위를 유지한다.

1. `products.name`
2. 사용자 `user_custom_inventory.name`

사입재고 배송대행은 `purchased_inventory_lots.product_name`에도 같은 정규화를 적용한다. 옵션명도 공백 차이로 실패할 수 있으므로 같은 정규화 기준을 적용한다.

화면과 저장 데이터는 가능한 한 원문을 유지한다. 비교용 키는 매칭에만 사용한다.

공백 제거 후 같은 키를 가진 후보가 여러 개면 자동 선택하지 않고 오류로 막는다. 예를 들어 `A BC`와 `AB C`가 둘 다 존재하면 업로드의 `ABC`는 어느 상품인지 확정할 수 없으므로 사용자가 상품명을 정리해야 한다.

승인 RPC의 상품명/재고명 불일치 방어도 같은 정규화 기준을 사용한다. 업로드 요청 시 통과한 항목이 승인 시 원문 공백 차이 때문에 `PRODUCT_MISMATCH`로 막히면 안 된다.

## 데이터 흐름

상품 구매:

1. 사용자가 장바구니에서 재고/구매 제한을 통과한 상품으로 검토 요청한다.
2. `stock_orders.pending`이 생성된다.
3. 관리자 승인 시 상품 금액이 예치금에서 차감되고 보유 재고가 적립된다.

엑시트몰 배송대행:

1. 사용자가 배송대행 양식을 업로드한다.
2. 업로드 단계에서 공백 무시 상품명 매칭으로 `product_id` 또는 `custom_inventory_id`를 확정한다.
3. 관리자 승인 시 보유 재고만 차감한다.
4. 배송비는 안내 금액으로 표시되며 예치금 잔액/예약액에는 영향을 주지 않는다.

사입재고 배송대행:

1. 사용자가 같은 배송대행 양식을 업로드한다.
2. 입고완료 재고명/옵션명을 공백 무시 기준으로 매칭하고 FIFO 배정한다.
3. 관리자 승인 시 입고완료 재고만 차감한다.
4. 예치금은 기존처럼 차감하지 않는다.

## 오류 처리

- 장바구니 재고 부족: 장바구니 행 경고와 주문 진행 차단.
- 주문 제출 시 재고 부족: 기존 서버 오류 매핑 유지.
- 공백 제거 후 중복 상품명: 업로드 단계에서 중복 후보를 보여주고 실패 처리.
- 공백 제거 후 미매칭 상품명: 기존 "존재하지 않는 상품명" 계열 오류 유지.
- 승인 시 재고 부족: 기존 승인 RPC 재고 부족 오류 유지.

## 테스트 계획

- 배송대행 승인 RPC: 엑시트몰 배송대행 승인 시 재고는 차감되고 예치금/거래내역은 변하지 않는지 확인한다.
- 예치금 계산: pending 배송대행 배송비가 가용액 예약에 포함되지 않는지 확인한다.
- 장바구니 계산: 재고 초과 상품이 부족 상태가 되고 주문 버튼이 비활성화되는지 확인한다.
- 상품 카드: 재고 수량 이상으로 장바구니에 담기지 않는지 확인한다.
- 매칭 유틸: 공백 1개/2개/없음 케이스가 같은 상품에 매칭되는지 확인한다.
- 매칭 유틸: 공백 제거 후 중복 후보가 있으면 실패하는지 확인한다.
- 사입재고 배정: 상품명과 옵션명 공백 차이를 무시하고 배정되는지 확인한다.

## 문서 수정 범위

- README의 배송대행 설명에서 "배송비 차감/예약" 표현을 "배송비 안내/별도 정산"으로 수정한다.
- 사용자/관리자 가이드에서 엑시트몰 배송대행 승인 시 예치금 차감이 없음을 명확히 한다.
- 사입재고 배송대행 안내는 기존 정책을 유지하되, 상품명 공백 매칭 기준이 동일함을 반영한다.
