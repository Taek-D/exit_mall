# 아키텍처

엑시트몰은 승인된 B2B 고객과 운영자가 같은 데이터 모델을 다른 권한으로 다루는 폐쇄몰이다. 화면은 고객 영역, 관리자 영역, 공개 인증 영역으로 나뉘고, 모든 중요한 변경은 서버에서 사용자 상태와 권한을 확인한 뒤 데이터베이스 함수나 제한된 쓰기 경로를 통해 처리한다.

## 시스템 구성

브라우저는 Next.js App Router 화면을 호출한다. 서버 컴포넌트는 Supabase 세션 쿠키를 읽어 목록과 상세 데이터를 조회하고, 클라이언트 컴포넌트는 폼 제출, 업로드, 실시간 알림처럼 상호작용이 필요한 곳에만 배치된다.

서버 액션은 고객 요청을 검증한 뒤 Supabase RPC를 호출하거나 제한된 테이블 쓰기를 수행한다. 예치금 차감, 보유 재고 증감, 배송대행 승인처럼 한 번에 맞물려야 하는 변경은 Postgres 함수가 원자적으로 처리한다. 서버 액션에서 여러 테이블을 임의 순서로 직접 갱신하면 동시 승인, 부분 실패, 감사 기록 누락이 생길 수 있다.

Supabase는 인증, Postgres, Storage, Realtime을 함께 맡는다. Postgres RLS는 사용자가 자기 행만 보도록 막고, 관리자 정책은 전체 운영 데이터를 열람·처리할 수 있게 한다. Storage는 상품 이미지처럼 공개 가능한 자료와 주문·입고·문의 파일처럼 비공개 파일을 버킷 단위로 분리한다.

엑셀 파일은 서버에서 파싱해 행 단위 업무 데이터로 바뀐다. 배송대행 양식과 입고리스트 양식은 서로 다른 헤더를 갖고, 잘못된 양식이 올라오면 저장 전에 거부한다. 업로드된 원본 파일은 검토와 송장 재업로드를 위해 보관하지만, 업무 판단의 기준은 파싱되어 저장된 행 데이터다.

## 대표 흐름

엑시트몰 상품 구매는 고객이 장바구니에서 검토 요청을 보내면 서버 액션이 활성 계정과 그룹 권한을 확인하고 `request_stock_order`를 호출하는 흐름이다. 함수는 상품 활성 상태, 재고, 1인 구매 한도, 가용 예치금을 검사하고 `stock_orders.pending`을 만든다. 관리자가 승인하면 `approve_stock_order`가 예치금과 마스터 재고를 차감하고 고객 보유 재고를 늘리며 변동 기록을 남긴다.

엑시트몰 배송대행은 고객이 배송 양식을 올리면 서버가 엑셀을 파싱하고 상품명으로 엑시트몰 보유 재고 또는 사용자 수기 재고를 찾는다. 저장된 업로드는 검토대기 상태가 되고, 승인 시 보유 재고가 차감된다. 송장 채움 파일은 같은 업로드에 재등록되어 행별 송장번호만 갱신하며, 원본 받는사람·상품·수량 데이터는 바꾸지 않는다.

사입재고 배송대행은 입고완료된 사입재고 로트에서만 수량을 배정한다. 고객이 같은 배송 양식을 올리면 상품명과 옵션명으로 로트를 찾고 오래된 로트부터 예약한다. 관리자가 승인하면 배정된 로트의 남은 수량만 차감하며 예치금은 건드리지 않는다.

입고리스트와 CS 문의는 고객과 관리자가 같은 게시글·댓글·첨부를 공유하는 비공개 협업 흐름이다. 사용자는 자기 요청만 보고, 관리자는 전체 요청을 검색·상태 변경·응답할 수 있다. 댓글 읽음 시각과 마지막 댓글 작성자 역할이 미확인 배지를 만든다.

## 영역별 책임

`app/`은 라우트, 서버 컴포넌트, 화면 조립을 맡는다. 화면은 데이터 조회와 렌더링을 연결하지만, 예치금·재고·승인 같은 핵심 변경 규칙을 직접 구현하지 않는다.

`lib/actions/`는 서버 액션의 입구다. 입력 검증, 권한 확인, RPC 호출, 캐시 갱신 경로를 담당한다. 사용자에게 보여줄 오류 문구는 여기에서 업무 문맥에 맞게 바꾼다.

`lib/admin/`, `lib/orders/`, `lib/inbound/`, `lib/support/`, `lib/guide/`는 화면에서 쓰는 조회·권한·상태 표시 보조 로직을 가진다. 이 영역들은 서버 액션을 우회해 업무 상태를 바꾸면 안 된다.

`lib/supabase/`는 서버, 브라우저, 미들웨어용 Supabase 클라이언트를 분리한다. service role 클라이언트는 공개 요청 처리나 파일 정리처럼 RLS를 우회해야 하는 좁은 경우에만 사용한다.

`supabase/migrations/`는 현재 업무 모델의 실제 데이터 계약이다. 테이블, RLS, RPC, Storage 정책이 모두 여기에 누적된다. 앱 코드가 어떤 상태 값을 기대한다면 마이그레이션의 CHECK와 RPC도 같은 상태 집합을 받아야 한다.

`components/`는 공용 UI와 도메인별 작은 화면 조각을 가진다. 운영 화면은 고밀도 테이블과 명확한 상태 배지를 우선하고, 장식적인 레이아웃보다 반복 작업의 스캔성과 실수 방지를 우선한다.

## 외부 의존성

Supabase 클라우드 또는 로컬 Supabase가 인증, DB, 파일 저장, 실시간 알림을 제공한다. Supabase가 멈추면 로그인, 목록 조회, 승인, 파일 접근이 모두 멈춘다.

Vercel 배포는 Next.js 앱 실행과 환경 변수 주입을 맡는다. `NEXT_PUBLIC_SITE_URL`이 실제 서비스 주소와 다르면 비밀번호 재설정 링크가 잘못된 도메인으로 갈 수 있다.

CJ대한통운 배송조회는 송장번호 조회 링크와 공개 조회 응답에 의존한다. 앱은 CJ 상태를 자체 보관하거나 자동 폴링하지 않으므로, 조회 실패는 배송대행 업무 상태를 바꾸지 않는다.
