# 작업 메모

## README 인코딩이 깨져 보일 때

증상: PowerShell 기본 읽기로 `README.md`나 `MASTER.md`를 열면 한글이 깨진다.

원인: 파일은 유니코드 인코딩인데 콘솔 기본 인코딩이 맞지 않을 수 있다.

대응: 문서를 읽을 때 `Get-Content -Encoding utf8`을 사용한다. 깨진 출력으로 업무 규칙을 판단하면 잘못된 내용을 새 문서나 코드에 옮기게 된다.

## 배송대행 양식의 A열은 저장 식별자가 아니다

증상: 배송대행 엑셀의 `고객주문번호`를 내부 주문번호처럼 쓰고 싶어질 수 있다.

원인: 현재 공식 배송대행 양식은 CJ 호환을 위해 A열을 허용하지만, 앱은 이 값을 업로드 호환용 참고값으로만 보고 시스템 식별자로 저장하지 않는다.

대응: 행 매칭과 송장 갱신은 저장된 업로드 ID와 행 번호, 파싱된 품목 정보를 기준으로 처리한다. A열을 업무 키로 쓰는 변경은 기존 업로드와 송장 재업로드의 의미를 바꾸므로 먼저 운영 정책을 바꿔야 한다.

## 배송대행 배송비는 예치금 예약액이 아니다

증상: 가용 예치금 계산에 배송대행 배송비를 빼고 싶어질 수 있다.

원인: 배송비는 행 수 기준 안내 금액이고, 운영상 별도 정산한다. 현재 예치금 예약액은 검토대기 상품 구매 금액만 포함한다.

대응: `computeAvailableDeposit`에서 배송비 예약을 다시 켜지 않는다. 배송비를 예치금 차감 대상으로 바꾸는 일은 입금, 승인, 거래 기록, 고객 안내를 함께 바꾸는 정책 변경이다.

## 상품명 매칭은 운영 데이터 품질에 민감하다

증상: 배송대행 업로드가 “같은 상품명의 상품이 여러 개”, “존재하지 않는 상품명”, 또는 “판매 중이지만 구매요청·보유재고가 없다”로 막힌다.

원인: 엑시트몰 배송대행은 현재 상품명으로 후보를 찾되, 후보는 그 고객의 보유 재고(수량 > 0)·검토대기 구매요청·수기 재고로 한정된다. 수량 0으로 소진된 보유 행은 후보가 아니다. 판매 중 카탈로그 전체는 후보가 아니라 안내 문구 분기(먼저 구매요청 vs 존재하지 않는 상품명)에만 쓴다. 중복 이름은 고객의 의도를 하나로 확정할 수 없다.

대응: 운영자가 상품 관리나 사용자 수기 재고 이름을 먼저 정리한다. “먼저 구매요청” 안내는 고객이 상품 구매요청을 만들면 풀린다. 임시로 첫 번째 상품을 고르는 방식은 오배송과 잘못된 재고 차감을 만들 수 있으므로 넣지 않는다.

## 사입재고 매칭 구분자는 양쪽이 같이 움직여야 한다

증상: 사입재고 배송대행에서 상품명과 옵션명이 맞는데도 배정 실패나 중복 판정이 난다.

원인: 사입재고 매칭 키는 정규화된 상품명과 옵션명을 NULL 문자 구분자로 합친 값이다. 업로드 액션과 사입재고 유틸이 같은 구분자 정책을 공유한다.

대응: 매칭 키 정책을 바꿀 때는 배송 업로드 액션과 사입재고 유틸, 관련 테스트를 함께 바꾼다. 한쪽만 바꾸면 미리보기와 승인 결과가 달라질 수 있다.

## 입고리스트와 배송대행 양식은 서로 거부해야 한다

증상: 고객이 입고리스트 양식을 배송대행에 올리거나 배송대행 양식을 입고리스트에 올린다.

원인: 둘 다 엑셀 파일이라 파일 확장자만으로는 구분할 수 없다.

대응: 헤더 검사와 알려진 양식 감지를 유지한다. 오류 메시지는 고객에게 어느 메뉴에서 어떤 템플릿을 다시 받아야 하는지 알려줘야 한다.

## 승인 후 되돌리기는 기능으로 만들지 않는다

증상: 승인된 상품 구매나 배송대행 요청에 고객 취소 버튼을 추가하고 싶어질 수 있다.

원인: 운영 정책상 고객 취소는 검토대기 상태에만 허용된다. 승인 이후에는 예치금, 재고, 송장, 고객 안내가 이미 업무 처리 상태에 들어간다.

대응: 승인 후 롤백이 필요해 보이는 요구는 새 버튼으로 처리하지 않는다. 운영상 조정이 필요하면 관리자 수동 조정, 별도 보상 거래, 문의 처리처럼 명시적인 운영 절차로 다룬다.

## 서버 액션 모듈은 async 함수만 export 할 수 있다

증상: `'use server'` 파일에서 순수 헬퍼(동기 함수, 상수)를 export 하면 `next build`가 실패한다.

원인: `'use server'` 모듈의 export는 모두 서버 액션으로 취급되어 async 함수만 허용된다. 테스트를 위해 순수 함수를 밖으로 빼려고 그 파일에서 export 하면 빌드가 깨진다.

대응: 단위 테스트 대상 순수 로직은 `'use server'`가 아닌 모듈(예: `lib/shipping-match.ts`)에 두고 서버 액션 파일에서 가져다 쓴다. 배송대행 후보/메시지 판정 로직도 이 방식으로 `lib/shipping-match.ts`에 순수 함수로 두고 테스트한다.

## 로컬 Supabase CLI 경로

증상: Windows에서 `supabase` 명령이 설치되어 있는데도 인식되지 않는다.

원인: 패키지 바이너리 심링크가 셸에서 잡히지 않을 수 있다.

대응: `./node_modules/supabase/bin/supabase.exe`를 직접 호출한다. DB reset과 타입 생성 명령을 문서화할 때 Windows 경로를 함께 적는다.
