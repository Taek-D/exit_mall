# 현재 상태

## 완료된 기능

예치금 기반 폐쇄몰의 기본 사용자 흐름이 구현되어 있다. 가입 신청, 관리자 승인·거절, 거절 사용자 재신청, 로그인, 아이디 찾기, 비밀번호 변경, 직접 비밀번호 재설정이 동작한다.

사용자 그룹 정책이 구현되어 있다. 1그룹은 전체 기능을 쓰고, 2그룹은 사입재고 배송대행·입고리스트·CS 문의·가이드·계정으로 제한된다. 미들웨어, 메뉴, 주요 서버 액션에 그룹 제한이 반영되어 있다.

상품 구매 검토 흐름이 구현되어 있다. 고객은 상품을 장바구니에 담아 검토 요청을 만들고, 관리자는 승인 또는 반려한다. 승인 시 예치금 차감, 마스터 재고 차감, 고객 보유 재고 적립, 변동 기록이 함께 처리된다.

엑시트몰 배송대행 흐름이 구현되어 있다. 고객은 배송대행 엑셀을 업로드하고, 관리자는 승인·반려·송장 재업로드·완료 처리를 할 수 있다. 송장번호는 고객 화면과 송장 포함 다운로드에 노출된다. 업로드 후보는 그 고객의 보유 재고·검토대기 구매요청·수기 재고에 있는 상품으로 한정되며, 그 밖의 판매 중 상품은 업로드 시점에 막고 "먼저 구매요청" 또는 "존재하지 않는 상품명"으로 안내한다.

사입재고 입고리스트와 사입재고 배송대행이 구현되어 있다. 고객은 입고 요청을 등록하고 관리자와 댓글로 진행하며, 입고완료 또는 관리자 수동 등록 재고를 사입재고 배송대행에 사용할 수 있다.

CS 문의 흐름이 구현되어 있다. 고객은 교환·반품·CS 문의를 등록하고, 관리자는 상태 변경과 댓글 응답을 할 수 있다. 관리자 댓글에는 이미지 첨부가 가능하다.

관리자 운영 화면이 구현되어 있다. 대시보드, 가입 승인, 입금 확인, 주문 검토, 배송대행 검토, 입고리스트, CS 문의, 상품 CRUD, 상품 엑셀 가져오기, 사용자 상세 관리, 잔액 부족 고객, 계좌 설정 화면이 있다.

보안과 안정화 작업이 상당 부분 반영되어 있다. 기본 보안 헤더, RLS, 비공개 Storage 정책, 배송대행 승인 동시성 방어, 상품명 불일치 방어, FK 인덱스 보강, RLS initplan 최적화, 주요 단위 테스트가 있다.

## 검증 상태

단위 테스트 파일은 상품 구매, 배송대행 파서와 RPC 주변 로직, 입고 요청, CS 문의, 사용자 그룹, 상품 가져오기, 관리자 사용자 관리, 배송조회, 재고 계산을 폭넓게 다룬다.

E2E 테스트는 인증 스모크, 사용자 그룹 로컬 시나리오, 가이드, CS 댓글 이미지 로컬 시나리오를 포함한다.

배송대행 후보 범위 축소 변경 시점에 `pnpm typecheck`, `pnpm lint`, `pnpm test`(55개 파일·489개), `pnpm build`가 모두 통과했다. 다음 기능 변경 전에는 현재 통과 여부를 다시 확인해야 한다.

## 남은 기능

CJ 자동 폴링과 배송 상태 캐싱은 구현되어 있지 않다. 현재는 송장번호를 이용한 조회 버튼과 외부 조회 결과 표시가 중심이다.

비CJ 택배사의 앱 내 배송 상태 조회는 구현되어 있지 않다. 비CJ 송장은 외부 조회 URL 또는 운영 안내로 다뤄야 한다.

사진이나 OCR 기반 상품 자동 등록은 구현되어 있지 않다. 상품 등록과 상품 엑셀 가져오기는 관리자가 입력하거나 업로드한 구조화 데이터를 기준으로 한다.

가격 비공개 후 문의 유도 UI는 구현되어 있지 않다. 현재 상품은 가격과 구매 가능 여부를 기준으로 상점에 표시된다.

담당자 자동 배정, 결제 PG 연동, 택배 자동 수거, 메일 발송 자동화는 구현되어 있지 않다.

상품명 기반 배송대행 매칭은 현재 운영 방식이다. 추후 식별자 기반으로 바꿀 수 있지만, 그때는 템플릿, 파서, 미리보기, 승인 RPC, 기존 데이터 호환 안내를 함께 바꿔야 한다.

## 현재 차단 요소

현재 확인된 즉시 차단 요소는 없다.
