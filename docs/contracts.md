# 외부 계약

## 웹 화면 접근

브라우저 사용자는 Supabase 세션 쿠키로 인증된다. 공개 경로 외 화면은 세션이 없으면 로그인 화면으로 이동하고, 활성 상태가 아니면 승인대기 화면으로 이동한다.

관리자 화면은 `/admin` 아래에 있다. 관리자 역할이 없는 사용자가 접근하면 고객 화면으로 이동한다. 2그룹 고객은 허용된 고객 경로 외로 접근하면 사입재고 배송대행 화면으로 이동한다.

레거시 호환 경로가 있다. `/orders/upload`는 엑시트몰 배송대행으로 이동하고, `/shipping-uploads`는 엑시트몰 배송대행으로 이동한다. 관리자 구 배송대행 경로도 새 관리자 배송대행 경로로 이동한다.

## 공개 가입 API

`POST /api/public/signup`은 가입 폼에서 호출하는 공개 엔드포인트다. 입력은 이메일, 비밀번호, 이름, 휴대폰 번호이며 형식 검증을 통과해야 한다.

성공하면 승인대기 화면으로 303 이동한다. 이미 거절된 사용자가 재신청하는 경우 기존 프로필을 다시 `pending`으로 돌리는 흐름을 허용한다.

검증 실패, 이미 처리할 수 없는 계정 상태, Auth 생성 실패는 가입 화면의 오류 흐름으로 돌아가야 한다. 응답은 공개 엔드포인트이므로 service role 키나 내부 DB 오류를 노출하면 안 된다.

## 레거시 주문 배송조회 API

`GET /api/orders/[id]/tracking`은 로그인 사용자가 레거시 `orders` 주문의 CJ 송장을 앱 안에서 조회하기 위한 엔드포인트다. 관리자는 전체 레거시 주문 조회가 가능하고, 일반 고객은 자기 레거시 주문만 조회할 수 있다.

성공 응답은 배송조회 결과를 JSON으로 반환한다. 실패 응답은 `{ code, error }` 형태와 HTTP 상태를 사용한다. 인증 실패, 권한 없음, 대상 없음, 외부 조회 실패는 서로 다른 상태로 구분되어야 한다.

이 API는 배송 상태를 앱 데이터에 저장하는 계약이 아니다. 외부 조회 결과는 호출 시점의 표시용이다. 배송대행 업로드 화면의 CJ 조회 버튼은 저장된 송장번호로 외부 조회 URL을 여는 방식이며, 배송대행 상태 전이는 관리자 승인, 송장 등록, 완료 처리로 결정된다.

## 엑셀 파일 계약

배송대행 템플릿은 첫 헤더 행에 고객주문번호, 받는분성명, 받는분전화번호, 받는분주소, 품목명, 내품명, 내품수량, 배송메세지1, 송장번호 계열의 열을 가진다. 받는사람, 전화번호, 주소, 상품명, 수량은 필수다. 수량은 1 이상의 정수여야 한다.

배송대행 A열 고객주문번호는 업로드 호환용 참고값이며 앱의 주문 식별자로 저장하지 않는다. 송장번호 열은 송장 재업로드 때 행별 송장 표시를 갱신하는 데 사용된다.

입고리스트 템플릿은 발송일, 상품명, 옵션, 재고수량, 사은품, 택배사, 송장번호, 비고 헤더를 가진다. 상품명과 재고수량은 필수이며 재고수량은 1 이상의 정수여야 한다.

잘못된 템플릿을 다른 메뉴에 업로드하면 저장 전에 거부한다. 파일 확장자가 맞아도 헤더가 맞지 않으면 계약 위반이다.

## 파일 다운로드

비공개 파일 다운로드는 화면에서 직접 Storage 공개 URL을 노출하는 방식이 아니다. 앱은 현재 사용자와 대상 요청의 관계를 확인한 뒤 제한된 시간의 링크를 발급한다.

상품 이미지는 공개 이미지 URL로 표시할 수 있다. 상품 이미지가 아닌 주문, 입고, 문의 파일은 공개 URL을 계약으로 제공하지 않는다.

## 환경 변수 계약

`NEXT_PUBLIC_SUPABASE_URL`과 `NEXT_PUBLIC_SUPABASE_ANON_KEY`는 브라우저에서 쓰는 공개 설정이다. 값이 비어 있으면 로그인과 공개 데이터 조회가 작동하지 않는다.

`SUPABASE_SERVICE_ROLE_KEY`는 서버 전용이다. 가입 재신청, 파일 정리, 제한된 관리자성 처리처럼 RLS 우회가 필요한 코드에서만 사용한다.

`NEXT_PUBLIC_SITE_URL`은 외부 콜백과 비밀번호 재설정 링크의 기준 주소다. 프로덕션에서 localhost를 가리키면 사용자가 메일 링크로 실제 서비스에 돌아오지 못한다.
