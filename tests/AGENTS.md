# tests 영역 기준

## 책임

`tests/`는 업무 규칙이 코드에서 계속 유지되는지 확인한다. 단위 테스트는 파서, 계산, 권한, 에러 매핑, 서버 액션 주변 순수 로직을 빠르게 검증하고, E2E 테스트는 인증과 주요 사용자 흐름이 실제 화면에서 이어지는지 확인한다.

## 경계

테스트가 현재 구현을 그대로 복사한 기대값만 확인하면 안 된다. 예치금 예약, 재고 부족, 중복 상품명, 잘못된 엑셀 양식, 권한 거부처럼 운영 사고를 막는 조건을 기대값으로 둔다.

테스트 파일은 운영 비밀이나 실제 고객 데이터를 포함하지 않는다. 엑셀 fixture는 최소 데이터로 재현 가능한 케이스만 담는다.

## 작성 방식

업무 규칙이 바뀌면 먼저 실패해야 할 케이스를 정한다. 특히 예치금, 재고, 배송대행, 입고, CS 문의 상태 전이는 정상 경로와 금지 경로를 함께 둔다.

파서 테스트는 정상 파일뿐 아니라 빈 파일, 필수값 누락, 잘못된 수량, 다른 양식 업로드, 모바일·한셀 호환 케이스를 확인한다.

권한 테스트는 관리자 성공만 확인하지 않는다. 다른 고객, 비활성 사용자, 2그룹 사용자, 소유자가 아닌 사용자가 막히는지 확인한다.

E2E 테스트는 너무 많은 데이터를 한 시나리오에 몰지 않는다. 로그인, 라우트 접근, 핵심 버튼 표시, 대표 제출 성공처럼 사용자가 실제로 밟는 경로를 짧게 유지한다.

## 실행 기준

일반 코드 변경 후 기본 확인은 다음 명령이다.

```bash
pnpm typecheck
pnpm test
```

라우트, 미들웨어, 인증, 브라우저 상호작용을 바꾼 경우 E2E를 추가로 확인한다.

```bash
pnpm test:e2e
```

배포 전 확인은 lint와 build를 포함한다.

```bash
pnpm lint
pnpm build
```
